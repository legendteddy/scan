# Scan v0.5.0 release notes (draft)

Scan v0.5.0 adds interoperability and CI receipts without turning Scan into a scanner runner or hosted service.

## Highlights

- **SARIF 2.1.0 export** from canonical Scan findings.
- **Bounded SARIF import** that preserves external-tool provenance, maps only safe repository-relative locations, keeps unmapped/review results as unknowns, and never treats zero results as project safety.
- **Reusable GitHub Action** that emits canonical state, self-contained HTML, SARIF, and a conservative Markdown summary without uploading artifacts or granting itself extra permissions.
- **Baseline-aware CI delta outputs** for artifacts, findings, and unknowns while preserving the rule that a resolved state delta is not proof of remediation.
- **Safer changed-scope context**: `--changed-since` no longer asks Git to run worktree conversion filters merely to determine changed paths.
- **Trusted CI policy boundary**: the GitHub Action ignores target `.scan/config.toml` by default; repository policy is an explicit workflow-owner opt-in.
- **Evidence/artifact binding hardening** for newly authored semantic evidence, while preserving compatibility with previously valid Scan 1.3/1.4 states.

## Trust boundaries retained

Scan v0.5.0 still does not execute target project code, run third-party scanners, upload SARIF, post PR comments, fetch baselines, contact AI models, or convert an empty finding list into a safety conclusion. External SARIF is evidence reported by its originating producer, not proof that Scan reproduced the condition.

## Release scope

This release is intentionally cut from the v0.5 line. Development work labeled v0.6—semantic-efficiency experiments, semantic-work token receipts, and the local report-history viewer—is **not part of the v0.5.0 release candidate**.

## Compatibility

- Python 3.11–3.13 remain the supported interpreter range.
- Canonical new reports use Scan state schema 1.4.
- Historical accepted schema generations remain readable according to the existing compatibility contract.
- The optional MCP extra remains available; v0.5 does not redefine the MCP trust boundary.

## Before publication

The candidate must pass the repository unit/ScanBench gates, installed-wheel acceptance, reusable Action smoke tests, and the native Windows/macOS/Linux release matrix. Publishing the PyPI package, GitHub release, or `v0.5.0` tag is a separate release action and is not implied by this draft.
