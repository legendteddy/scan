# v0.5 GitHub Action contract

## Purpose

This slice packages Scan as a reusable composite GitHub Action. It runs deterministic Scan Core against an already checked-out project and emits four receipts: canonical state JSON, a self-contained HTML report, SARIF 2.1.0, and a conservative Markdown job summary.

The action does not execute target code, contact an AI model, upload SARIF, upload workflow artifacts, post PR comments, or grant itself repository permissions. Those are separate workflow decisions.

## Default trust boundary

- Python is provided by `actions/setup-python`, pinned to the exact v7.1.0 commit used by this repository.
- Scan runs in `offline` privacy mode.
- The default baseline is `none`, avoiding accidental trust in a stale or repository-controlled prior state.
- Output is written to a fresh directory under `RUNNER_TEMP`, outside the inspected project.
- The action does not create `.scan` in the target by default.
- Generated SARIF contains only canonical findings. Deterministic Core normally has zero semantic findings unless higher-level evidence has been added elsewhere.
- The job summary keeps findings, unknowns, artifact coverage, and check coverage separate. Zero findings is explicitly not presented as a clean bill of health.

## Basic workflow

```yaml
permissions:
  contents: read

steps:
  - uses: actions/checkout@v7
  - id: scan
    uses: legendteddy/scan@v0.5.0
    with:
      path: .
      mode: deep
      redact: standard
```

The `v0.5.0` reference above is the intended release tag once v0.5 is published. During development, use a reviewed commit SHA or `uses: ./` inside this repository.

## Outputs

The action returns absolute paths for `state`, `report`, `sarif`, and `summary`, plus machine-readable counts for findings, unknowns, assessed checks, total checks, discovered artifacts, semantic-analysis completion, baseline status, baseline-delta availability, and Scan producer version. When a validated baseline is used it also exposes artifact added/changed/removed counts and finding/unknown new/modified/resolved counts. Delta count outputs are empty when no comparison exists; they are never fabricated as zero.

These paths can be handed to later workflow steps without Scan itself performing any upload.

## Baseline-aware pull request summary

Supply a previously retained, validated Scan state through `baseline` to enable comparison. The Markdown job summary then adds a **Since validated baseline** section, and the action exposes outputs such as `delta-available`, `artifacts-added`, `artifacts-changed`, `findings-new`, `findings-resolved`, `unknowns-new`, and `unknowns-resolved`.

```yaml
- id: scan
  uses: legendteddy/scan@v0.5.0
  with:
    path: .
    baseline: ${{ runner.temp }}/trusted-baseline/state.json

- if: steps.scan.outputs['delta-available'] == 'true'
  run: echo "Changed artifacts: ${{ steps.scan.outputs['artifacts-changed'] }}"
```

Scan does not download or trust a baseline automatically. The workflow owner is responsible for obtaining the baseline from a trusted source. `resolved` means absent from the current state; it is not proof that a problem was fixed.

## Optional artifact retention

As of October 2026, the current `actions/upload-artifact` release is v7.0.2. A hardened workflow can pin its exact commit:

```yaml
- uses: actions/upload-artifact@cf430e030ddbb5b0abf93d22962f4752f3646cd9 # v7.0.2
  with:
    name: scan-receipts
    path: |
      ${{ steps.scan.outputs.state }}
      ${{ steps.scan.outputs.report }}
      ${{ steps.scan.outputs.sarif }}
      ${{ steps.scan.outputs.summary }}
```

## Optional GitHub code-scanning upload

SARIF upload is intentionally separate because it requires repository support and `security-events: write`. GitHub's current CodeQL action exposes `upload-sarif` and documents that permission requirement. The current v4 tag resolves to commit `9b3254085494b55a0f7c4c2b3d2d52cc712ce370`.

```yaml
permissions:
  contents: read
  security-events: write

steps:
  - uses: actions/checkout@v7
  - id: scan
    uses: legendteddy/scan@v0.5.0
  - uses: github/codeql-action/upload-sarif@9b3254085494b55a0f7c4c2b3d2d52cc712ce370 # v4
    with:
      sarif_file: ${{ steps.scan.outputs.sarif }}
```

Uploading an empty Scan SARIF file does not mean the project is safe. It only means the supplied canonical Scan state contained no findings exportable as SARIF results.

## Inputs

- `path`: project directory, relative to `GITHUB_WORKSPACE` unless absolute.
- `mode`: `quick`, `deep`, or `forensic`; default `deep`.
- `redact`: `none`, `standard`, or `strict`; default `standard`.
- `baseline`: `none`, `auto`, or an explicit state path; default `none`.
- `changed-since`: optional advisory local Git ref.
- `excludes`: optional newline-separated exclusion patterns.
- `sensitive-paths`: optional newline-separated sensitive-path patterns.
- `output-directory`: optional explicit output directory. Leaving it empty keeps outputs under `RUNNER_TEMP`.
- `fail-on`: optional `PARTIAL` or `ERROR` threshold.
- `job-summary`: append Markdown to `GITHUB_STEP_SUMMARY`; default `true`.
- `python-version`: Python version requested from setup-python; default `3.12`.

## Failure behavior

When Scan can create canonical state but a requested coverage threshold fails, the action still writes state, report, SARIF, summary, and action outputs before returning the nonzero Scan exit code. This preserves evidence for diagnosing the failure.

Source/privacy/internal failures that prevent canonical state construction fail without fabricating receipts.

## Non-goals

This slice is not an AI reviewer, scanner adapter, GitHub check-run service, SARIF uploader, PR-comment bot, or release gate that declares code safe. Those layers may consume Scan outputs later, but must preserve the same evidence/unknown boundaries.
