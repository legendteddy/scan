# v0.6 local report history viewer

`scan serve` is a read-only local HTTP viewer for validated Scan 1.3/1.4 state receipts. It is a developer convenience layer over canonical state; it does not broaden Scan's inspection authority.

## Usage

```bash
# Serve the current receipt directory on loopback only.
scan serve .scan

# Serve a directory containing multiple validated state JSON receipts.
scan serve path/to/history --port 8765

# Serve one exact state receipt.
scan serve .scan/state.json
```

The default bind is `127.0.0.1:8765`. A non-loopback host is rejected unless the caller explicitly supplies `--allow-network`.

## What is exposed

The server accepts at most 256 immediate `*.json` candidates from the selected directory, with a 32 MB ceiling per receipt. Larger history sets fail closed instead of being silently truncated. Every candidate must validate as canonical Scan state before it appears in the index. Invalid, duplicate, non-file and symlinked JSON candidates are ignored and counted.

Available routes are deliberately narrow:

- `/` - validated receipt index;
- `/report/<receipt-id>` - report rendered in memory from that canonical state;
- `/state/<receipt-id>.json` - canonical state JSON;
- `/compare/<older>/<newer>` - human-readable comparison for the same project lineage;
- `/compare-json/<older>/<newer>` - canonical comparison payload;
- `/healthz` - local liveness response.

There is no filesystem directory listing and no generic file-serving route. Project source files, neighboring HTML, logs, credentials and arbitrary files are not reachable through the server.

## History and comparison semantics

`scan serve` does not silently create or retain history. A directory becomes a history set only because the user or workflow already placed validated Scan state receipts there. This keeps retention policy explicit.

Receipts are ordered by their recorded completion timestamp. Comparison links are offered only between receipts with the same project name and source-locator lineage. `resolved` continues to mean "absent from the newer canonical state"; it is not proof that an issue was fixed or independently verified.

## Trust boundary

The local viewer:

- does not execute target code;
- does not scan or read the project tree beyond the explicitly selected receipt JSON files;
- does not perform network fetches;
- does not modify receipts or the target;
- applies `Cache-Control: no-store`, `nosniff`, and no-referrer response headers;
- uses restrictive Content Security Policy headers for generated index/comparison pages and the self-contained Scan report;
- binds to loopback unless network exposure is explicitly authorized.

`--allow-network` only permits a non-loopback bind. It does not add authentication, TLS, access control, discovery, publishing or remote storage. If a user chooses to expose the viewer beyond the local machine, network security remains their responsibility.

## Non-goals for this slice

This slice does not add automatic history archiving, hosted dashboards, team sharing, report mutation, live file watching, target execution, AI analysis, remote storage or audience-specific report modes.
