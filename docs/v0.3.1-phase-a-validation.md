On non-Windows runners, the three skips are exactly:

- `test_windows_handle_path_representation_and_short_name_alias`: native Windows
  canonical handle paths.
- `test_windows_junction_ref_config_and_inventory_escape`: native Windows junction

- `test_replaced_parent_junction_is_rejected_before_reading`: Windows opened-handle
  junction race regression.

All three execute and pass on Windows. No privilege-related skips occurred in the
native Windows release gate. macOS passes both the original exact-worktree-grant
test and the new ancestor-alias confinement regression. ScanBench's unchanged
contract contains 12 fixtures, 55 assertions and five dimensions; all three native
release jobs log all 12 fixture passes and all five dimension passes. Their
separate installed acceptance steps each log `PASS: Scan v0.3 installed-CLI
acceptance`. These steps continue after a Core failure if wheel installation
succeeded, retaining the job failure while ensuring downstream gates execute.

Windows root cause: a final handle path was compared to the caller's textual
path using only case folding. Hosted runner aliases such as short TEMP paths can
refer to the same legitimate file using different names. The fix resolves the
authorized root and exact expected target before opening, resolves the opened
handle path, normalizes extended/UNC namespaces, case and separators, and requires
both exact canonical target equality and containment in the canonical root before
reading. Regular-file, pre-open/opened identity and bounded-read checks remain.
Regression coverage exercises native short-name resolution and extended-prefix,
case, separator and UNC representation differences, plus both junction races.

macOS root cause: external grants were validated by walking from `/`, rejecting
normal ancestor aliases such as `/var` to `/private/var`. Each exact invocation
grant now resolves strictly to an existing canonical directory; only a candidate
resolving to that exact directory is authorized. All subsequent metadata reads
remain relative to that canonical boundary and reject internal links. Parent and
sibling grants still fail, and `commondir` requires its own exact authorization.

Reproduction results:

- Parent/absolute Git HEAD traversal no longer reads an external ref. The report
  records the rejected metadata boundary instead of resolving an outside commit.
- Oversized refs, Git config, packed refs, HEAD and Scan config fail safely.
  Reads have explicit byte limits, including live-growth detection.
- External worktree metadata remains unavailable without exact invocation grants;
  both worktree and common metadata grants permit legitimate bounded provenance.
- Event attributes, active URIs, remote/relative resources, CSS imports/URLs and
  escape variants, scripts beyond the inert authoritative state, frames/plugins,

- Real builder-authored local-model evidence reuses only after current producer
