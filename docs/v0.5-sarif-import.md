# v0.5 SARIF import adapter contract

## Purpose

`scan import-sarif` converts third-party SARIF 2.1.0 results into a new validated Scan state. It is an adapter, not a scanner: Scan does not execute the originating tool, fetch remote content, or independently reproduce imported findings.

```bash
scan import-sarif .scan/state.json external-results.sarif \
  --output .scan/imported-state.json \
  --report .scan/imported-report.html
```

## Trust boundary

- The base Scan state must already validate.
- Only SARIF 2.1.0 is accepted in this slice.
- SARIF files are bounded to 64 MB and 10,000 results.
- Only repository-relative file URIs that map to canonical Scan file artifacts can become findings.
- Absolute paths, URI schemes, parent traversal, `uriBaseId`, and unmapped locations are never guessed into the project.
- `kind: fail` (or the SARIF default when `kind` is absent) may become a Scan finding.
- `review` and `open` results are retained as Scan unknowns because they require human/tool follow-up rather than representing a confirmed fail result.
- `pass`, `notApplicable`, and `informational` results are counted as ignored and are not promoted into findings or controls.
- Imported evidence is `static`, produced by `external-tool`, and explicitly states that Scan did not independently reproduce it.
- Imported prose is re-redacted using the current Scan state's redaction level before it enters canonical state or report.
- A mapped file is marked `partial`, not `analyzed`, because imported scanner evidence is rule-scoped and the scanner configuration was not independently established by Scan. Whole-project `analysis_complete` remains false.

## Identity

When available, SARIF `partialFingerprints` or `fingerprints` contribute to stable imported finding identity. Otherwise Scan derives identity from the tool, rule, mapped repository-relative locations, and message. Scan does not invent GitHub fingerprints or line hashes.

## Severity

SARIF result levels map conservatively:

- `error` ? `high`
- `warning` ? `medium`
- `note` ? `low`
- `none` ? `informational`

Scanner-specific severity extensions are not interpreted in this first adapter slice.

## Location handling

SARIF 2.1.0 recommends result locations, while GitHub code scanning requires at least one location to display an alert. Scan's importer is stricter for canonical findings because a Scan finding must reference a known project artifact. Results without a safely mapped canonical artifact are retained as unknowns instead of being dropped or attached to a guessed path.

## Non-goals

This slice does not execute scanners, download CI artifacts, upload SARIF, infer absolute-path roots, resolve remote URIs, translate SARIF 2.2, claim runtime verification, or mark overall semantic coverage complete.
