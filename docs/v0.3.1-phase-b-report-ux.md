## Design rationale

The report answers **Know what your AI actually inspected** with one target title,
one canonical condition, four exact counts, and an explicit unknown/readiness
notice. A compact wrapping navigation links the seven stages of the reading flow.
Findings carry severity and evidence type, then impact and recommended next step;
confidence, limits, verification instructions and proof are progressively disclosed.

The navy report identity remains; gradients, glow, glass, giant radii, ornamental
metrics and the fixed 48px mobile title are removed. One stylesheet token system
replaces the accumulated override layers. The two shipped shells remain identical;
no packaging refactor was introduced. All primary structures wrap at 390px. Wide
check/inventory/ledger tables live exclusively inside labeled, keyboard-focusable
audit disclosures. Every relationship and component is rendered, including artifact
endpoints and records beyond the initial summary. There are no invented edges.

Baseline changes, freshness and Git advisory scope are independent blocks. First
scans explain the absence of a baseline and disclose the seven zero reconciliation
receipts. Repeat scans show new/resolved/modified records and explain that resolved
means absent now, not fixed. Verified reuse retains its original observation time
and has a separate reuse time in the ledger. Unknowns remain visible even with zero
findings. Actions are a bounded, deduplicated set from supported canonical content;
complete action and continuation data remains available in the appendix.

Evidence IDs, locators and section fragment anchors remain available. Native
fragment navigation into evidence automatically expands ancestor disclosures in
the tested Chromium. Every receipt can also be opened with the keyboard without
JavaScript. Complete technical records and the exact authoritative state remain
in the HTML. Raw JSON is excluded from the primary reading flow.

## Rendered review and remaining trade-offs

The local bundle is named `phase-b-review` and includes five before/after widths
(390, 768, 1024, 1280, 1536), full-page and first-screen PNGs, three print PDFs,
representative HTML/JSON cases, the new Scan-on-Scan report, inspection sheets and
validation logs. CI recreates the current reports and captures on Ubuntu. The
before comparison uses the exact Phase A renderer/shell on the **same current
canonical self-review state**; it is a layout comparison, not a claim to reproduce
an unavailable earlier semantic review or historical snapshot.

Manual review covered the mobile stress cases, all five self-review widths,
findings, baseline/reuse, coverage/unknowns, architecture, actions, expanded audit,
and printed opening/check/inventory/ledger pages. The first pass found an oversized
mobile header and a sparse printed check table when one check linked hundreds of
receipts. The final layout reduces header metadata and prints check rows as labeled
blocks; native detail expansion preserves metric grids. No UI quality score is used.

Accessibility inspection found one H1, ordered headings, main/nav landmarks,
explicit severity text, sufficient measured text contrast, visible focus, 44px
navigation/summary targets, table scopes, native keyboard disclosure, a skip link
and reduced-motion handling. Focus on the dark header uses a light outline. This
is a browser/markup inspection, not a full screen-reader certification.

Intentional horizontal scrolling is limited to expanded audit tables at narrow
widths. No primary content scrolls horizontally at any required viewport. Full audit
PDFs remain long and their inventory/ledger uses compact type to retain all columns
and evidence. Closed disclosures expand in tested Chromium print; other engines
remain unverified and may need manual expansion. Browser Find's disclosure reveal
is browser-dependent. Complete raw technical views are retained in HTML but omitted
from print where they duplicate the readable report/receipts. Owner judgment of the
actual rendered experience remains the final acceptance gate.
