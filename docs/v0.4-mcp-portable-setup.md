# Scan v0.4 portable MCP setup

Status: **development slice; not a v0.4 release approval**

This slice turns the read-only MCP foundation into an install-and-connect workflow. It does not change Scan Core's evidence semantics, execute target code, or publish a v0.4 package.

## Install

When v0.4 is released, install the optional MCP extra:

```bash
python -m pip install "scan-skill[mcp]"
```

The base `scan-skill` package remains dependency-free. The MCP extra installs the official MCP Python SDK v2 line used by the local bridge.

## Diagnose before configuring a host

Run:

```bash
scan-mcp doctor /absolute/path/to/project
```

Machine-readable output:

```bash
scan-mcp doctor /absolute/path/to/project --json
```

Doctor checks:

- Python 3.11+;
- Scan package version;
- installed MCP SDK and supported v2 major line;
- project-root access;
- an absolute Python launcher suitable for minimal host environments;
- a canonical Scan 1.4 static/offline snapshot;
- no target-code execution or network action;
- no new `.scan` output directory;
- MCP server factory initialization.

Doctor does not start a long-lived MCP server and does not modify the inspected project.

## Portable launch model

Host configuration uses the currently running Python interpreter as an **absolute executable path** and launches:

```text
<absolute-python> -m scan_core.mcp_server <absolute-project-root> --redact standard
```

This avoids relying on a host's shell activation, current directory, or full `PATH`. Local MCP hosts commonly start stdio servers with a minimal environment, so absolute launch paths are the portable default.

The project root is fixed in the generated launch arguments. MCP calls cannot broaden it.

## Generate host configuration

Use:

```bash
scan-mcp config HOST /absolute/path/to/project
```

Supported hosts:

```text
codex
claude-desktop
claude-code
cursor
vscode
```

Generate every supported form at once:

```bash
scan-mcp config all /absolute/path/to/project
```

Use a custom server name:

```bash
scan-mcp config codex /absolute/path/to/project --name project-scan
```

Preserve Scan privacy controls in generated launch arguments:

```bash
scan-mcp config cursor /absolute/path/to/project \
  --redact strict \
  --sensitive-path "private/**"
```

## Host outputs

### Codex

`scan-mcp config codex ...` emits a `config.toml` block using `mcp_servers.<name>`, `command`, and `args`.

Paste it into the Codex MCP configuration and verify with the host's MCP listing command.

### Claude Desktop

`scan-mcp config claude-desktop ...` emits the `mcpServers` JSON object used by Claude Desktop. Merge the generated server entry into the existing desktop configuration rather than replacing unrelated servers.

### Claude Code

`scan-mcp config claude-code ...` emits a complete `claude mcp add ... -- <stdio launch command>` command.

### Cursor

`scan-mcp config cursor ...` emits an `mcpServers` JSON object suitable for Cursor's MCP configuration.

### VS Code

`scan-mcp config vscode ...` emits a `servers` JSON object with `type: "stdio"`, matching VS Code's MCP configuration shape.

## Backward compatibility

The original foundation syntax remains valid:

```bash
scan-mcp /absolute/path/to/project
```

It is treated as:

```bash
scan-mcp serve /absolute/path/to/project
```

Explicit form:

```bash
scan-mcp serve /absolute/path/to/project
```

The server remains local stdio. There is no network listener.

## Security and privacy boundary

The portable setup layer does not weaken the v0.4 MCP foundation:

- absolute project root fixed at launch;
- no target-code execution;
- no network egress by the Scan MCP process;
- bounded artifact reads;
- traversal/link/reparse protections;
- digest checking against the server snapshot;
- standard or strict deterministic redaction;
- configured sensitive-path blocking;
- explicit stale-snapshot behavior.

The connected host/model is still a separate trust boundary and may transmit MCP tool outputs according to its own architecture and policy.

## Acceptance gates

This slice is ready to merge only when:

1. the base package remains usable without the MCP dependency;
2. the built wheel with `[mcp]` passes `scan-mcp doctor`;
3. all five host configuration generators succeed from the installed wheel;
4. generated launchers use an absolute Python executable and absolute project root;
5. legacy `scan-mcp PATH` remains compatible;
6. doctor creates no target `.scan` output;
7. the MCP protocol suite remains green;
8. the full Core suite remains green;
9. Windows, macOS, and Linux release gates install the MCP extra from the built wheel and pass portable setup checks;
10. source/control files remain UTF-8 without BOM.

## Current publication boundary

Until a v0.4 release is explicitly approved and published, PyPI `scan-skill==0.3.1` remains the latest released package and does **not** contain this development slice.
