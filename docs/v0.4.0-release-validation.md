## What 0.4.0 adds

### Read-only local MCP bridge

Scan can be installed with the optional MCP extra and served over local stdio. The base package remains dependency-free.

```bash
python -m pip install "scan-skill[mcp]"
scan-mcp doctor /path/to/project
scan-mcp config codex /path/to/project
```

The bridge fixes the project root at server startup, does not execute target code, performs no Scan-owned network egress, and does not write `.scan` output into the inspected target. Bounded artifact reads enforce path containment, sensitive-path blocking, byte ceilings, cached-snapshot identity, redaction, and stale-byte detection.

### Portable MCP setup

`scan-mcp doctor` validates the installed bridge without starting a host. `scan-mcp config` produces host-ready launch configuration for Codex, Claude Desktop, Claude Code, Cursor and VS Code using absolute Python/project paths so host startup does not depend on shell activation or a full `PATH`.

### Bounded semantic continuation

The MCP application exposes a separate in-memory semantic workspace tied to one deterministic Scan snapshot. Authorized agents can add evidence-linked components, relationships, findings, unknowns and check assessments through the existing `SemanticStateBuilder` contract. Semantic evidence is bound to current artifact bytes, invalid mutations roll back, changed bytes make the workspace stale until reset, and observed/runtime claims are rejected in this static-only slice. Canonical Scan 1.4 state and self-contained HTML can be exported as read-only MCP resources without modifying the target project.

### Agent-Honesty ScanBench

A deterministic false-confidence gate now verifies five specific evidence-discipline boundaries:

1. tests exist ≠ tests passed;
2. inventory/hash coverage ≠ semantic review;
3. static evidence ≠ runtime verification;
4. unchanged bytes ≠ freshly reviewed evidence;
5. missing findings/evidence ≠ safe or ready.

The gate reports PASS/FAIL only. It deliberately does not produce a blended intelligence, honesty or quality score and does not claim an agent can never hallucinate.

## Trust and privacy boundary

The Scan MCP server is a local stdio process. The connected AI/MCP host is a separate trust boundary and may transmit tool results according to that host's architecture and policy. A PASS from Scan, ScanBench, Agent-Honesty ScanBench, Doctor or CI is not a factual security certification of an inspected project.

The release candidate must preserve the distinction between deterministic inventory, static semantic assessment and runtime observation. Runtime/observed evidence is not synthesized by the MCP semantic workspace in 0.4.0.

## Publication boundary

Release artifacts must be built once from the exact approved release commit, retained externally, verified from fresh isolated installs, and attached unchanged to the GitHub Release. The configured GitHub → PyPI Trusted Publisher must then publish those exact release assets through OIDC; no long-lived PyPI API token is required.

Creating `v0.4.0`, publishing the GitHub Release, and allowing Trusted Publishing to upload to PyPI remain separate consequential actions requiring owner approval after the release-prep PR and exact-head validation are green.
