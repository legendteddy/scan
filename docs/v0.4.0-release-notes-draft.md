# Scan v0.4.0 release notes (draft)

Scan v0.4.0 turns the v0.3 deterministic core into a more portable agent-facing inspection platform while preserving the same evidence discipline and read-only default.

## Highlights

- Optional local stdio MCP bridge via `scan-skill[mcp]` and `scan-mcp`.
- Portable MCP doctor/config generation for Codex, Claude Desktop, Claude Code, Cursor and VS Code.
- Snapshot-consistent, bounded artifact access with stale-byte detection, sensitive-path blocking and redaction.
- In-memory semantic continuation workspace tied to one Scan snapshot, using canonical Scan 1.4 state rather than a second state format.
- Evidence-linked semantic authoring for components, relationships, findings, unknowns and checks without modifying the inspected project.
- Static-only semantic boundary: runtime/observed claims are rejected unless separately established outside this workspace.
- Agent-Honesty ScanBench gates five common false-confidence upgrades without inventing a model intelligence score.
- Cross-platform installed-wheel validation continues on Windows, macOS and Ubuntu with Python 3.11/3.12/3.13 coverage.

## Trust boundary

The Scan MCP process itself is local stdio, does not execute target code and performs no Scan-owned network egress. The connected AI/MCP host is a separate trust boundary and may handle tool results according to its own architecture and policy.

Scan still distinguishes inventory, content reads, static semantic assessment and runtime observation. A PASS is not a security certification of the inspected project.
