This document records the release gate for the clean v0.5 line. It is evidence of checks performed, not a security certification or proof of defect-free behavior.

## Candidate lineage

The release candidate is reconstructed from the v0.5 SARIF-import feature tip (`48652dd`) plus the bounded P0 trust-hardening patch. It intentionally excludes later v0.6 development merges.

## Required installed/cross-platform gates

The repository workflow must build and install the wheel on Windows, macOS, and Linux, then verify:

- [ ] installed `scan --version` reports `0.5.0`;
- [ ] installed SARIF export produces valid SARIF 2.1.0;
- [ ] installed SARIF import preserves external provenance and does not set whole-project semantic completeness;
- [ ] the reusable Action emits state/report/SARIF/summary without writing `.scan` into its target by default;
- [ ] the full native test suite and ScanBench v1 pass;
- [ ] `scripts/v05_acceptance.py` passes, including the hostile Git clean-filter sentinel.

## CI policy requirement

The reusable Action must ignore target-controlled `.scan/config.toml` by default. `project-config: true` is the explicit workflow-owner opt-in. The effective policy source is recorded in canonical extensions by the trust-hardening patch.

## SARIF claims

- Imported SARIF is external-tool evidence; Scan does not claim independent reproduction.
- Review/open or safely unmappable fail results remain unknowns.
- Pass/not-applicable/informational results do not become Scan findings.
- Zero SARIF results are not a clean bill of health.
- Import byte/result/text ceilings remain enforced.

## Release boundary

Do not include v0.6 semantic-efficiency, semantic-work receipt, or local report-history development in the v0.5.0 release tree.

## Publication boundary

Creating the `v0.5.0` tag, GitHub Release, PyPI publication, or changing `main` is outside this validation step and requires the normal release approval and successful release gates.
