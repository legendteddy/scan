# v0.4 Agent-Honesty ScanBench

Status: v0.4 development contract.

## Purpose

Agent-Honesty ScanBench is a deterministic regression gate for a narrow question:

> Does Scan keep weak evidence from being silently upgraded into a stronger claim?

It is **not** an LLM leaderboard, an honesty score, a factual audit of an arbitrary project, or proof that a model will never hallucinate. It exercises Scan's own state, semantic-builder, validator, baseline and evidence-reuse contracts against known false-confidence failure modes.

Run the complete gate from a source checkout or installed development wheel:

```bash
python -m scan_core.agent_honesty
python -m scan_core.agent_honesty --json
```

Run one scenario:

```bash
python -m scan_core.agent_honesty tests-exist-not-passed
```

The full repository test suite also invokes the complete gate, so these claim boundaries are release regressions rather than optional examples.

## Scenarios

### 1. Tests exist ≠ tests passed

A synthetic project contains an application file and a readable test file. Scan may inventory and hash both, but the `testing_and_reliability` check must remain `not_assessed` and `unverified` until actual test execution or another authorized verification supplies appropriate evidence.

The benchmark fails if mere test-file presence is converted into a passing testing claim.

### 2. Inventory ≠ semantic review

A safely readable source file receives deterministic inventory/content identity only. The artifact must remain `content_read`, not `analyzed`; `coverage.analysis_complete` must remain false; and the semantic/runtime unknown must remain explicit.

The benchmark fails if hashing or discovery is presented as semantic understanding.

### 3. Static read ≠ runtime verification

The benchmark creates valid static semantic evidence and then deliberately attempts to mark a correctness check as `observed`. The semantic builder/validator must reject the state because no observed evidence exists.

The benchmark fails if static evidence can satisfy an observed/runtime claim.

### 4. Unchanged file ≠ freshly reviewed

A prior semantic observation is attached to stable file bytes, stored as the previous Scan state, and scanned again without changing the file. Scan may safely reuse eligible evidence, but the evidence must be labeled `verified_reuse`, preserve its original observation time, and retain its original depth. The current artifact remains `content_read`; the higher-level check is not silently promoted to assessed.

The benchmark fails if unchanged bytes are relabeled as a fresh semantic review.

### 5. Missing evidence ≠ safe

The benchmark deliberately attempts to create a finding and an assessed security check without evidence. Both unsupported upgrades must be rejected. The untouched deterministic state has zero findings but still records unknowns and readiness as `not established`.

The benchmark fails if "no finding recorded" or an evidence-free assertion can become a clean bill of health.

## Result contract

Each scenario reports only PASS/FAIL plus the guarded claim and diagnostic detail. The JSON form contains:

- `agent_honesty_scanbench_version`
- `scan_version`
- one record per scenario
- overall `passed`
- `score: null`

No blended honesty, intelligence or quality score is calculated. A passing gate means only that these five known false-confidence upgrades are currently blocked by Scan's deterministic contracts.

## Safety and scope

The benchmark uses temporary synthetic projects. It does not execute target code, use network access, or modify a user's inspected project. Scenario files are test data, not instructions to execute. Runtime claims are tested by attempting invalid state construction, not by running the synthetic target.

This gate complements the existing ScanBench v1 fixture suite. The original five dimensions remain unchanged:

- inventory completeness
- state integrity
- evidence correctness
- privacy integrity
- safety-boundary compliance

Agent-Honesty ScanBench is a separate claim-discipline gate so the published v1 fixture dimensions are not silently redefined.
