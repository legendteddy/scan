# Scan v0.6 efficiency benchmark harness

Status: development slice.

## Purpose

Measure whether Scan's semantic-efficiency work actually reduces repeated AI work before making token-savings claims.

The harness compares validated canonical Scan states and optional exact token receipts from the model host. It does **not** call a model, estimate tokens from file size or lines of code, infer cost savings from `priority_paths`, or weaken Scan's coverage rules.

## Run it

From a source checkout:

```bash
python scripts/benchmark_efficiency.py \
  --run baseline=.scan/baseline-state.json \
  --run repeat=.scan/repeat-state.json \
  --pretty \
  --output .scan/efficiency-benchmark.json
```

If the model host exposes exact usage, normalize it into a small JSON receipt and attach it by the same run label:

```json
{
  "provider": "example-host",
  "model": "example-model",
  "input_tokens": 12345,
  "output_tokens": 678
}
```

```bash
python scripts/benchmark_efficiency.py \
  --run baseline=.scan/baseline-state.json \
  --run repeat=.scan/repeat-state.json \
  --usage baseline=.scan/baseline-usage.json \
  --usage repeat=.scan/repeat-usage.json \
  --pretty
```

`total_tokens` may be supplied by the host. If it is absent but exact `input_tokens` and `output_tokens` are both present, the harness derives only their arithmetic sum and marks that fact. Missing token counts remain unavailable.

## Metrics

For each run the harness records:

- discovery, semantic-analysis and check-completion flags from canonical coverage;
- artifact counts by status and inspection origin;
- evidence counts by inspection origin;
- higher-level evidence carrying an explicit `evidence_class`, split into fresh and `verified_reuse` counts;
- baseline reuse counters already present in Scan state;
- canonical artifact/finding/unknown delta counts;
- local Git changed-scope `priority_paths` and deleted-path counts when present;
- exact host token counts only when supplied.

For multiple runs, the first run is the benchmark baseline. Later runs report raw count deltas against it. The harness deliberately does not calculate percentage token savings or claim equal defect-detection quality.

## Recommended experiment

1. Choose a representative repository and pin the same model/host configuration.
2. Produce an initial deep semantic review and retain its canonical state plus exact host usage if available.
3. Make a small known change.
4. Repeat with the validated baseline and `--changed-since` so Scan can expose delta, reusable evidence and `priority_paths`.
5. Compare the two states with this harness.
6. Review findings, unknowns and coverage alongside token counts. Lower token usage is not a success if material findings disappear or coverage becomes weaker without being reported as partial.
7. Repeat across several repositories before publishing any numerical savings claim.

## Boundary

This slice does not add a token budget, provider SDK, dependency graph, embeddings, automated model runner, dynamic UX tests, policy engine, or benchmark leaderboard. It measures existing evidence so the next optimization can be chosen from data rather than assumption.
