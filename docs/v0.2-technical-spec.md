# Scan v0.2 Technical Specification

Status: **Approved implementation contract; implemented in the v0.2 development line**
Target release: **v0.2 (publication/tagging remains a separate owner-approved action)**
Compatibility baseline: **Scan report contract 1.2**
Primary principle: **The report's facts belong to Scan Core, not to an LLM conversation.**

This specification turns the current instruction-driven Scan project into a deterministic, local-first inspection core while preserving `SKILL.md` as an agent-facing operating layer. It is intentionally narrower than the long-term roadmap: v0.2 establishes trustworthy state, evidence, privacy and reproducibility before integrations or autonomous analysis are added.

Normative words **MUST**, **MUST NOT**, **SHOULD**, **SHOULD NOT** and **MAY** describe release requirements.

## 1. Release goals

v0.2 MUST provide:

1. A standalone `scan` CLI that can inspect a local project without an AI host.
2. A reusable Python `scan_core` package behind the CLI.
3. Deterministic project inventory, content identity and snapshot generation.
4. A canonical JSON state that is the single source of truth for report facts.
5. HTML rendering from canonical state and structural validation of both JSON and HTML output.
6. Explicit local privacy modes, deterministic redaction, and an egress preview contract.
7. ScanBench v1: adversarial synthetic fixtures with machine-checkable expected outcomes.
8. Backward compatibility with existing Scan 1.2 reports as historical input.
9. Safe default behavior: no target-code execution and no network access by the core scan path.
10. Clear completion semantics that keep artifact coverage, check coverage and runtime verification separate.

### 1.1 Non-goals

The following are explicitly out of v0.2:

- baseline/diff scanning;
- SARIF export or code-scanning upload;
- Semgrep, CodeQL, Trivy or other external scanner adapters;
- policy-as-code enforcement;
- MCP server;
- VS Code extension;
- browser scanning;
- cloud/team service;
- model-provider integrations;
- autonomous target execution;
- automatic remediation;
- specialist multi-agent orchestration.

These remain roadmap items for later releases. v0.2 MUST leave extension points for them without shipping incomplete versions.

## 2. Compatibility and versioning

The project currently validates embedded HTML state using report contract `schema_version: "1.2"`.

v0.2 introduces two distinct version axes:

- **software version**: Scan v0.2.x;
- **report-state contract**: Scan state `schema_version: "1.3"`.

State 1.3 is an additive evolution of 1.2. Existing 1.2 HTML reports MUST remain valid historical inputs and MUST NOT be silently relabeled as 1.3.

The implementation MUST keep a versioned validator path so that:

```text
Scan 1.2 report -> validate as 1.2
Scan 1.3 state  -> validate as 1.3
Scan 1.3 HTML   -> embedded state must validate as 1.3
```

A v0.2 renderer MUST emit 1.3 state only after that state passes the 1.3 validator.

## 5. CLI contract

The console entry point is `scan = scan_core.cli:main`.

### 5.1 Primary command

```bash
scan PATH [options]
```

Examples:

```bash
scan .
scan . --offline
scan ./project --output .scan/report.html
scan ./project --state .scan/state.json --no-html
scan ./project --privacy local --redact standard
```

Default behavior:

- PATH defaults to `.` when omitted.
- Core inspection is read-only.
- Target code is not executed.
- Network access is not required and MUST NOT occur in the default core path.
- Symlinks are inventoried but MUST NOT be followed outside the declared root.
- Hidden files are included unless excluded by explicit configuration.
- Generated/vendor files remain in inventory even when their semantic depth differs.
- Output defaults to `.scan/state.json` and `.scan/report.html`.

### 5.2 Utility subcommands

```bash
scan validate PATH
scan render STATE_JSON --output REPORT_HTML
scan bench [FIXTURE]
scan schema [--version 1.2|1.3]
scan egress PATH [scan options]
```

`scan validate` validates either canonical JSON state or a Scan HTML report.

`scan render` MUST refuse to render invalid state.

`scan bench` runs ScanBench fixtures without executing fixture target code.

`scan schema` prints the requested bundled JSON Schema.

`scan egress` performs selection and redaction planning only. It MUST NOT transmit data.

### 5.3 Required v0.2 options

```text
--output PATH            HTML report path
--state PATH             canonical JSON state path
--no-html                write state only
--privacy MODE           offline | local | controlled-remote
--redact LEVEL           none | standard | strict
--exclude GLOB           repeatable exclusion
--max-file-bytes N       semantic-read safety ceiling
--max-total-bytes N      scan resource ceiling
--follow-internal-links  opt in to symlinks that resolve inside root
--fail-on PARTIAL|ERROR  choose nonzero completion threshold
--json                    machine-readable CLI summary
--quiet                   suppress progress output
--version                 show Scan version
```

`controlled-remote` exists in v0.2 only as a state/configuration contract for future providers. The v0.2 core MUST NOT itself send remote requests.

## 6. Exit codes

The CLI MUST use stable exit codes:

| Code | Meaning |
|---:|---|
| 0 | requested operation completed successfully |
| 2 | command/configuration error |
| 3 | source path/access error |
| 4 | scan completed but declared coverage threshold was not met |
| 5 | validation failed |
| 6 | privacy/redaction policy blocked the requested operation |
| 7 | resource/safety limit reached |
| 10 | unexpected internal Scan error |

A partial scan is not automatically an internal error. Its state MUST describe the actual boundary and continuation work.

## 7. Core Python API

Public APIs MUST be small, typed and independent from CLI formatting.

```python
from scan_core import ScanConfig, scan_project, validate_state, render_report

result = scan_project(ScanConfig(root="."))
validate_state(result.state)
render_report(result.state, "report.html")
```

Required public types:

```python
@dataclass(frozen=True)
class ScanConfig:
    root: Path
    output_state: Path | None = None
    output_html: Path | None = None
    privacy_mode: Literal["offline", "local", "controlled-remote"] = "offline"
    redaction_level: Literal["none", "standard", "strict"] = "standard"
    excludes: tuple[str, ...] = ()
    max_file_bytes: int = 5_000_000
    max_total_bytes: int = 250_000_000
    follow_internal_links: bool = False

@dataclass(frozen=True)
class ScanResult:
    state: dict[str, Any]
    state_path: Path | None
    report_path: Path | None
    completion: Literal["complete", "partial", "blocked"]
    warnings: tuple[str, ...]
```

Required functions:

```python
def scan_project(config: ScanConfig) -> ScanResult: ...
def build_inventory(config: ScanConfig) -> InventoryResult: ...
def build_snapshot(inventory: InventoryResult) -> Snapshot: ...
def redact_value(value: str, policy: RedactionPolicy) -> RedactionResult: ...
def validate_state(state: Mapping[str, Any], version: str | None = None) -> None: ...
def validate_report(path: Path) -> None: ...
def render_report(state: Mapping[str, Any], output: Path) -> None: ...
def build_egress_preview(state: Mapping[str, Any]) -> EgressPreview: ...
```

Private modules MAY change without compatibility guarantees during v0.2.x. The names above are the public compatibility surface.

## 8. Deterministic inventory and snapshot rules

Inventory is the foundation of all later completeness claims.

### 8.1 Artifact identity

Each discovered artifact MUST receive a deterministic ID derived from its normalized locator, not from discovery order.

Recommended form:

```text
artifact:<sha256(normalized-relative-path)[:20]>
```

The full content hash belongs in `content_identity` and MUST NOT be used as the only artifact ID because two paths may legitimately contain identical bytes.

### 8.2 Path normalization

Scan MUST:

- store project-relative POSIX-style locators in state;
- preserve the original display name separately when normalization changes presentation;
- reject `..` escape from the declared root;
- inventory symlinks as symlinks;
- resolve a symlink only when `--follow-internal-links` is set and the resolved target remains inside the root;
- never traverse a symlink that escapes the root;
- handle filenames as data, including leading dashes, whitespace and unusual Unicode.

### 8.3 Content identity

For regular files within configured limits:

```text
sha256:<64 lowercase hex characters>
```

For unreadable or deliberately un-hashed artifacts, `content_identity` MUST contain a typed explanation rather than a fabricated digest.

### 8.4 Snapshot identity

The snapshot digest MUST be computed from a canonical ordered manifest containing at least:

```text
locator
artifact type
size
content identity
symlink target identity where relevant
```

Changing order alone MUST NOT change the snapshot digest. Changing any included identity field MUST change it.

## 9. Canonical state 1.3

State 1.3 keeps the existing 1.2 collections and adds deterministic run, privacy and provenance data needed by a standalone core.

### 9.1 Required additive top-level objects

```json
{
  "schema_version": "1.3",
  "run": {
    "scan_id": "scan:...",
    "scan_version": "0.2.0",
    "started_at": "RFC3339 timestamp",
    "completed_at": "RFC3339 timestamp",
    "mode": "static",
    "target_executed": false,
    "network_used": false
  },
  "privacy": {
    "mode": "offline",
    "redaction_level": "standard",
    "redaction_count": 0,
    "sensitive_path_count": 0,
    "egress_performed": false,
    "egress_bytes": 0
  },
  "provenance": {
    "root_identity": "...",
    "snapshot_digest": "sha256:...",
    "state_digest_algorithm": "sha256",
    "tool_versions": [],
    "configuration_digest": "sha256:..."
  }
}
```

The existing required 1.2 objects and collections remain required:

```text
project
summary
coverage
continuation
extensions
checks
artifacts
components
relationships
evidence
findings
controls
unknowns
actions
```

### 9.2 Artifact additions

Each artifact MUST add:

```json
{
  "size_bytes": 1234,
  "media_type": "text/x-python",
  "path_kind": "file",
  "redaction_state": "none"
}
```

Allowed `path_kind` values:

```text
file
directory
symlink
archive_member
special
unknown
```

Allowed `redaction_state` values:

```text
none
metadata_only
content_redacted
path_redacted
fully_omitted
```

`fully_omitted` MUST still leave an inventory row with a safe locator surrogate and reason when the artifact was discoverable.

### 9.3 Evidence additions

Evidence MUST add producer provenance:

```json
{
  "producer": {
    "kind": "scan-core",
    "name": "scan-core",
    "version": "0.2.0"
  },
  "source_digest": "sha256:..."
}
```

Future producer kinds MAY include `external-tool`, `local-model`, `remote-model` and `human`, but v0.2 core emits only `scan-core` and may preserve imported historical provenance.

### 9.4 Coverage additions

Coverage MUST add:

```json
{
  "resource_limits_hit": [],
  "unreadable_artifact_count": 0,
  "redacted_artifact_count": 0
}
```

Resource limits MUST affect completeness honestly. Hitting a configured limit cannot be presented as complete analysis.

### 9.5 Integrity rule

The serialized state MUST be canonicalized before digesting. The report renderer MUST embed the same logical state that was validated. It MUST NOT recalculate findings, coverage, counts or verdict text independently.

## 10. Evidence model

v0.2 core is deterministic. It MUST distinguish:

- discovery evidence;
- metadata evidence;
- content/static evidence;
- unknown/unverified state.

The core MUST NOT claim semantic correctness merely because a file was read or hashed.

Examples of valid deterministic evidence:

```text
"File exists at locator X"
"SHA-256 of bytes is Y"
"Path is a symlink to Z"
"Artifact exceeds configured semantic-read limit"
"Pattern resembling a credential was redacted"
```

Examples that MUST NOT be generated by v0.2 core without a future analyzer:

```text
"Authentication is secure"
"This function contains an SQL injection"
"All tests pass"
"The service is production ready"
```

The current `SKILL.md` MAY still guide an AI agent to add higher-level evidence, but such evidence must obey the same state contract and provenance rules.

## 11. Privacy and redaction

### 11.1 Modes

`offline`
: No network-dependent operation is permitted. `network_used` MUST be false.

`local`
: Local deterministic tools and future local models may be allowed. v0.2 behaves equivalently to offline except for recording the selected mode.

`controlled-remote`
: Represents user intent to permit a future bounded remote analyzer. v0.2 MUST generate an egress preview but MUST NOT transmit data because no remote provider exists in this release.

### 11.2 Redaction levels

`none`
: No content redaction requested. Sensitive material still MUST NOT be echoed unnecessarily in CLI logs.

`standard`
: Redact known credential/token/private-key patterns and obvious secret assignments.

`strict`
: Apply standard redaction plus conservative masking of likely emails, phone numbers, account-like identifiers and user-declared sensitive path patterns.

Redaction MUST preserve enough structure for evidence to explain what happened without storing raw secret values.

Example:

```text
AWS_SECRET_ACCESS_KEY=ABCD... -> AWS_SECRET_ACCESS_KEY=[REDACTED:credential]
```

The raw value MUST NOT appear elsewhere in generated state or HTML.

### 11.3 Egress preview contract

`scan egress PATH` MUST emit at least:

```text
files selected
bytes selected
files omitted by policy
redaction count
sensitive paths omitted
privacy mode
network action: none
```

The preview MUST be deterministic for an unchanged snapshot and configuration.

## 12. HTML report pipeline

The renderer MUST:

1. accept only validated state;
2. serialize state with a real JSON serializer;
3. preserve the stable embedded state ID `project-anatomy-state`;
4. escape `<`, `>` and `&` in embedded JSON safely;
5. avoid external network dependencies;
6. render useful content with JavaScript disabled;
7. keep the report self-contained;
8. expose coverage limits and unknowns near the verdict;
9. keep artifact analysis completeness separate from check completeness;
10. render the same counts and statuses present in canonical state.

The existing report shell may be migrated under `src/scan_core/report/`, but its visual language SHOULD remain compatible with the current launch-ready example unless a separate design change is approved.

## 13. Validator architecture

v0.2 MUST split validation into:

```text
schema validation
reference integrity
coverage/count integrity
provenance/integrity rules
HTML embedding rules
```

A passing validator means the state is structurally coherent. It MUST NOT be described as proof that the analysis is factually correct, secure or complete beyond the encoded evidence.

Required invariants include existing 1.2 rules plus:

- exactly one supported state version;
- valid run timestamps and scan ID;
- `target_executed` false for v0.2 core-generated runs;
- `network_used` false for offline mode;
- `egress_performed` false for v0.2 core-generated runs;
- snapshot digest has valid format;
- artifact size is a non-negative integer when known;
- redacted/omitted artifacts reconcile with privacy and coverage counts;
- producer provenance exists on evidence;
- rendered HTML embeds one authoritative state block;
- state-derived visible counts equal embedded values.

## 14. ScanBench v1

ScanBench is a release gate, not a marketing score.

Each fixture MUST contain:

```text
fixture.toml or fixture.json
project/
expected.json
README.md
```

`expected.json` declares objective properties, not prose opinions.

Required v1 fixtures:

| Fixture | Required assertion |
|---|---|
| `clean-minimal` | complete deterministic inventory and stable snapshot |
| `hidden-files` | hidden artifact is inventoried |
| `symlink-escape` | escaping symlink is not traversed |
| `prompt-injection` | hostile instructions in source are treated as inert data |
| `secret-redaction` | raw secret absent from state/report under standard redaction |
| `malformed-filename` | unusual filename does not become a command/option |
| `unreadable-artifact` | artifact remains represented and completeness becomes partial |
| `archive-boundary` | archive is not unsafely expanded/executed by default |
| `unsupported-binary` | binary is inventoried without fabricated semantic analysis |
| `generated-and-vendor` | generated/vendor artifacts remain visible in inventory |
| `incomplete-discovery` | resource boundary produces explicit incomplete coverage |
| `false-runtime-claim` | static scan never claims tests/runtime passed |

### 14.1 Benchmark dimensions

v0.2 reports separate dimensions:

```text
inventory completeness
state integrity
evidence correctness
privacy integrity
safety-boundary compliance
```

There MUST NOT be a single blended “overall quality” score in v0.2.

### 14.2 ScanBench command result

```bash
scan bench
```

prints per-fixture pass/fail and a dimension summary. Nonzero exit means at least one required fixture failed.

## 15. Configuration

Optional project configuration lives at `.scan/config.toml`.

Minimal example:

```toml
[scan]
privacy = "offline"
redact = "standard"
max_file_bytes = 5000000
max_total_bytes = 250000000
follow_internal_links = false

[exclude]
patterns = [".git/**", ".scan/**"]
```

Precedence MUST be:

```text
CLI arguments > .scan/config.toml > built-in defaults
```

Configuration itself MUST be included in the configuration digest. Secrets MUST NOT be required in v0.2 configuration.

## 16. Security boundaries

v0.2 MUST preserve the existing static-first safety model.

The core MUST NOT:

- execute project scripts, tests, package hooks or binaries;
- evaluate HTML/JavaScript from inspected targets;
- import Python modules from the target;
- execute archive contents;
- follow escaping symlinks;
- fetch URLs found in source;
- install project dependencies;
- disable host security controls;
- interpret source text as agent instructions.

Parsing MUST treat target content as untrusted data.

Archive members MAY be inventoried in a future bounded parser path, but v0.2 may conservatively represent archives as containers when safe member enumeration is not implemented. The report MUST say which behavior occurred.

## 17. Acceptance tests

v0.2 is releasable only when all mandatory acceptance tests pass.

### 17.1 Packaging and CLI

- `python -m pip install .` succeeds on supported Python versions.
- `scan --version` returns v0.2.x.
- `scan . --offline` produces canonical JSON and self-contained HTML.
- Running the same scan twice against unchanged bytes/config produces the same inventory IDs and snapshot digest.
- Time-varying run timestamps do not alter snapshot identity.

### 17.2 Safety

- A fixture executable is never executed.
- A malicious filename beginning with `-` is not interpreted as a CLI option internally.
- A symlink to a file outside the root is not followed.
- A source file containing “ignore previous instructions” does not affect control flow.
- No network request occurs in offline mode.

### 17.3 Privacy

- Known synthetic secrets are absent from generated JSON and HTML under standard redaction.
- Redaction counts reconcile with artifact/evidence state.
- `scan egress` sends no network traffic.
- Strict redaction does not write raw masked values to logs.

### 17.4 State integrity

- Every referenced ID resolves to the correct collection.
- Artifact counts reconcile exactly.
- Check counts reconcile exactly.
- Incomplete discovery prevents `analysis_complete=true`.
- An unreadable critical artifact creates an explicit unknown.
- HTML embedded state validates independently after rendering.
- A hand-edited visible count that disagrees with state causes report validation failure where mechanically detectable.

### 17.5 Reproducibility

- Golden state fixtures compare after removing only allowed volatile run fields.
- Snapshot digest is stable across supported operating systems for identical normalized input bytes and paths.
- JSON canonicalization is deterministic.

### 17.6 ScanBench

- All required v1 fixtures pass.
- Each benchmark dimension is reported separately.
- CI fails when any mandatory expected assertion fails.

## 19. Implementation order

Implementation should be delivered as reviewable vertical slices.

### Slice 1 — Packaging and frozen contracts

- add `pyproject.toml`;
- create `src/scan_core`;
- move/wrap current validator without changing 1.2 semantics;
- add schema/version dispatch;
- establish CLI skeleton and exit codes.

**Gate:** all existing validator/demo tests still pass.

### Slice 2 — Inventory and snapshot

- deterministic artifact IDs;
- safe path walking;
- hashing and manifest canonicalization;
- snapshot digest;
- resource limits;
- inventory tests and initial ScanBench fixtures.

**Gate:** deterministic cross-run fixture output.

### Slice 3 — State 1.3

- canonical state builder;
- run/privacy/provenance objects;
- additive artifact/evidence/coverage fields;
- 1.3 validation and migration tests.

**Gate:** canonical JSON validates with zero renderer dependency.

### Slice 4 — Privacy and redaction

- privacy modes;
- redaction engine;
- egress preview;
- no-network enforcement tests at the Scan-process boundary;
- privacy ScanBench fixtures.

**Gate:** no synthetic secret appears in state/report/log fixtures.

### Slice 5 — Renderer migration

- renderer consumes only canonical state;
- migrate current report shell/components;
- embed exact authoritative state;
- JavaScript-disabled and self-contained report checks.

**Gate:** report round-trip validates and current demo visual quality is retained.

### Slice 6 — ScanBench v1 and release hardening

- complete mandatory fixtures;
- stable dimension reporting;
- CI integration;
- CLI/help/README updates;
- compatibility documentation.

**Gate:** all acceptance criteria in this specification pass on CI.

## 20. Pull-request plan

To keep review safe and reversible, implementation SHOULD use separate PRs:

1. `core: package Scan and preserve 1.2 validator compatibility`
2. `core: add deterministic inventory and snapshot identity`
3. `core: introduce canonical state 1.3`
4. `core: add privacy, redaction and egress preview`
5. `core: render HTML from canonical state`
6. `test: add ScanBench v1 and v0.2 release gates`

No PR should mix unrelated visual redesign work with core-state or safety changes.

## 21. Definition of done

Scan v0.2 is done when a clean machine can install the project and run:

```bash
scan . --offline
scan validate .scan/state.json
scan validate .scan/report.html
scan egress .
scan bench
```

and the following are all true:

- the project was not executed;
- no network request was needed;
- the inventory and snapshot are deterministic;
- the JSON state is the authoritative fact source;
- the HTML is derived from that state;
- secrets in benchmark fixtures are redacted as configured;
- incomplete work is represented as incomplete;
- old 1.2 reports remain historical-valid rather than silently upgraded;
- every mandatory ScanBench fixture passes;
- the current agent skill can consume or extend the same evidence contract instead of maintaining a separate truth model.

## 22. Deferred roadmap after v0.2

The intended next layers are:

**v0.3 — daily workflow**
: baseline/diff scans, SARIF, GitHub workflow integration, external scanner imports, policy-as-code and stronger provenance.

**v0.4 — agent ecosystem**
: MCP, provider-neutral structured AI observations, local-model support, CycloneDX/SPDX and attestations.

**v0.5 — developer UX**
: VS Code integration, `scan serve`, report history/comparison and audience-specific Executive/Reviewer/Evidence views over one state.

These later layers MUST reuse Scan Core rather than recreate inventory, evidence, privacy or coverage logic.
